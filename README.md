# ЧЁРТ AI

Backend и веб-панель проекта Chert-ai1.

## Возможности

- HTTP API статуса и настроек.
- Запуск и остановка отдельного worker-процесса (пока только heartbeat).
- Журнал действий и ошибок в `data/audit.jsonl`.
- Ограничение частоты запросов и размера JSON.
- Проверка доступности публичной страницы Galaxy of Dating без входа в аккаунт.

## Локальный запуск

Требуется Node.js 20 или новее.

```bash
CHERT_HOST=127.0.0.1 npm start
```

Откройте http://127.0.0.1:8787. Для локального режима API доступен с loopback без токена.

## Развёртывание на Render

Создайте **Web Service** из репозитория `ikorbulatskiy-cpu/Chert-ai1`.

- Runtime: Node
- Build command: `npm install`
- Start command: `npm start`
- Environment: `CHERT_HOST=0.0.0.0`
- Environment: `CHERT_API_TOKEN` = случайный секрет не короче 32 символов (лучше 48–64 случайных символа).
- Node version: 20 или новее.

Render автоматически предоставляет переменную `PORT`. Не задавайте её вручную. Не помещайте токен в Git, README, frontend или URL. Вызовы защищённых API должны отправлять заголовок `Authorization: Bearer <CHERT_API_TOKEN>`. Публичный `GET /api/health` не требует токена для health check.

При внешнем bind приложение откажется запускаться, если токен отсутствует или короче 32 символов. Используйте HTTPS URL Render.

**Важно про бесплатный тариф:** сервис может засыпать при бездействии. Локальные файлы бесплатного сервиса не являются надёжным постоянным хранилищем. Для сохранения настроек и журнала между перезапусками подключите постоянное хранилище/БД или тариф с диском.

## Проверки

```bash
npm run check
npm test
```

Smoke test запускает backend локально, проверяет health, отказ без токена, авторизованный доступ к настройкам, старт/остановку worker и журнал. Он не создаёт Render deployment и не проверяет реальный игровой аккаунт.

## API

- `GET /api/health` — health check, открыт.
- `GET /api/status` — статус.
- `GET /api/settings`, `PUT /api/settings` — настройки.
- `POST /api/bot/start`, `POST /api/bot/stop` — управление worker-заготовкой.
- `POST /api/galaxy/check` — проверка публичной страницы.
- `GET /api/logs?limit=100` — журнал.

Все API-маршруты, кроме health, требуют Bearer-токен при удалённом размещении.

## Ограничения Galaxy

Интеграция проверяет только публичную страницу. Она не авторизуется, не читает cookies/localStorage, не получает игровой профиль и не читает/отправляет сообщения. Настройки мониторинга и автоответов пока только сохраняются и не выполняют игровые действия. Для реальной интеграции нужен официальный поддерживаемый интерфейс или разрешённый безопасный механизм.

## Данные

По умолчанию настройки и журнал находятся в `data/`, исключённом из Git. Для тестов можно переопределить каталог через `CHERT_DATA_DIR`.
